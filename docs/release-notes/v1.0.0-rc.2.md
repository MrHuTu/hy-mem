# hy-mem v1.0.0-rc.2 发布说明

发布日期：2026-10-30 ｜ 产物：`hy-mem-1.0.0-rc.2-win64.zip`（178 MB，Windows 免安装绿色包）

## 一、做了什么优化

写记忆太慢，一条要半分钟，批量更慢。本版把写入链路拆开重构，快了 8 倍：

**优化前**：4 条记忆批量写入 187 秒，单条同步 28 秒。
**优化后**：4 条批量 22 秒，单条同步 9 秒。

具体做了三件事：

1. **锁只锁该锁的**。原来整个写入过程（含两次 LLM 调用，各 8~15 秒）都持着全局写锁，别的进程只能干等。现在拆成三段：LLM 抽取和向量计算放锁外并行，锁内只留最后的判重落库（2~11 秒 → 1.5 秒）。

2. **多条合并成一次判定**。原来 4 条记忆各判各的重复（4 次 LLM 调用）；现在同一批合并成 1 次判定，每条记忆的溯源关系（原文→结论）逐条保留不错挂。

3. **换了更快的 LLM**（见下方模型对比）。

## 二、修复了什么 Bug

| Bug | 现象 | 修复 |
|---|---|---|
| 删除残留幽灵节点 | `delete` 后向量库残留可检索的"尸体"记忆，删了还能搜到 | 删除时级联清扫向量节点 |
| 并发写裸崩 | 双进程同时写，第二进程报 `sqlite readonly` 硬失败且提示误导 | 改为结构化重试 + 明确报错（E_DB_BUSY/E_LOCK） |
| LLM 空响应裸失败 | 网关偶发返回空内容，整条写入直接失败 | 自动重试 3 次（仅空响应），配额/鉴权错误不重试 |
| 两处隐藏 NameError | 平移代码时漏 import，只在并发路径触发，单测全绿也炸 | 修复；平移/重构后必跑 pyflakes 静态扫 |
| 全批无可提取时崩溃 | 一批记忆全是闲聊（无可记事实），批提交段未初始化变量崩溃 | 正常路径必须扛住，"没什么可记"是合法结论 |

## 三、LLM 模型实测对比与推荐

记忆系统的两个 LLM 任务（从原文抽取事实、判断新旧记忆关系）实测了百炼平台上 7 个模型，统一用真实任务 prompt、每个跑 3 轮：

### 延迟与稳定性

| 模型 | 平均耗时 | 坏响应 | 备注 |
|---|---|---|---|
| **tongyi-intent-detect-v3** | 0.5s | 质量不合格 | 只会输出键值对、丢字符——专用意图分类器，做不了开放生成，淘汰 |
| **tongyi-xiaomi-analysis-flash** | **0.7s** | 0/6 | ✅ **推荐** |
| deepseek-v4.1-flash-1017 | 1.7s | 0/6 | 备选，质量同样过硬 |
| qwen3.8-flash | 5.0s | 0/6 | 可用但慢 |
| qwen3.8-27b | 5.7s | 0/6 | 同上 |
| qwen3.7-plus | 10.2s | 0/6 | 太慢 |
| ysjx（GLM-5.3-Flash，旧配置） | ~13s | **1/8 空响应** | 淘汰：推理 token 烧光预算，内容一个字没输出就被截断 |

### 为什么推荐 tongyi-xiaomi-analysis-flash

1. **最快且稳**：0.7 秒/次，6 轮零坏响应，比第二名快 2.4 倍。写入链路里 LLM 是速度大头，它直接把单条写入从 13 秒压到 9 秒。
2. **质量实测过硬**：抽取的技术名词零失真（路径、模型名原样保留）；判定新旧关系时，给足判定标准后分类正确；真实链路里还主动把新旧记忆合并成演化链（不是简单堆叠）。
3. **同平台同密钥**：与向量模型（qwen3.7-text-embedding-flash）同在百炼平台，一把 key 通吃，零额外配置。
4. **反直觉教训**：最快的 intent-detect（0.5s）反而不能用——它是给固定类目分类训练的，遇到"把口语改写成陈述句"这种开放生成任务就输出歪结构。**选模型不能只看速度榜，要用真实任务实测输出质量**。

### 切换方法

`config.json` 的 `llm.model` 改为 `tongyi-xiaomi-analysis-flash` 即可（密钥不变）。回切改回旧值就行，无迁移成本。

## 六、已知事项

- serve 服务空闲 30 分钟自动退出，之后首次调用会多 ~2.8 秒冷启动（自动再拉起）；介意可 `hy-mem serve --idle-exit 0` 常驻
- 语义检索回答不了"我昨天做了什么"这类时间问题（语义匹配天然不沾边），用 `list --since` 时间窗——工具描述里已写明
- 密钥走用户级环境变量，config.json 零密钥
