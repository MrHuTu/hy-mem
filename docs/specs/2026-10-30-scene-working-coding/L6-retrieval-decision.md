# L6 消费侧决策：检索该不该带 schema

日期：2026-10-30
环境：沙箱 `hymem-l6ret-6pyrmg8l`（30 条 hy-mem 架构事实 → evolve 出 6 条 L6 schema），
ultra 模式，嵌入 `qwen3.7-text-embedding-flash`（1024 维）。

## 一、问题

`search` 默认会带 L6（`schema_limit=10`），实测 evolve 后同样的 query 从 5 条变 11 条
（5 fact + 6 schema），schema 分数只有 0.03 量级。要不要默认关掉整条 L6？

关掉的后果是 evolve 变成只写不读——等于弃用。所以先测：只走语义正路时，
schema 到底能不能被正常命中。

## 二、测量方法与结果

对每条 query 直接调 `graph_store.vector_search(layers=["l6_schema"], score_threshold=0)`
拿原始余弦分（绕开 RRF，避免分数被替换），同时跑一次 `schema_limit=0` 的正常检索取
fact top1 作为同尺度参照。

| 类 | query | schema top1 | ≥0.4 | ≥0.5 | fact top1 |
|---|---|---|---|---|---|
| 相关 | 密钥和凭证怎么管，能不能进 git | 0.4113 | 1 | 0 | 0.4686 |
| 相关 | 发布流程有什么规矩，能不能带未验证的东西发 | 0.4653 | 1 | 0 | 0.4185 |
| 相关 | 并发和资源处理上他是怎么定的 | 0.4491 | 2 | 0 | — |
| 相关 | 配置的优先级怎么排 | 0.5760 | 1 | 1 | 0.6386 |
| 相关 | 向量库和嵌入模型是怎么命名的 | 0.5547 | 1 | 1 | 0.6443 |
| 相关 | 检索阈值凭什么定那个数 | 0.4687 | 1 | 0 | 0.6019 |
| 相关 | hy-mem 的写锁粒度是多少 | 0.5557 | 6 | 1 | 0.7453 |
| 相关 | 他的工程习惯是什么，在意什么 | 0.2952 | 0 | 0 | — |
| 相关 | hy-mem 的异步队列怎么消费 | 0.4584 | 2 | 0 | 0.7595 |
| 对照 | 今天天气怎么样 | 0.2572 | 0 | 0 | — |
| 对照 | 帮我把这段话翻译成英文 | 0.2451 | 0 | 0 | — |
| 对照 | python 怎么读取 csv 文件 | 0.2687 | 0 | 0 | — |
| 对照 | 推荐几部科幻电影 | 0.2441 | 0 | 0 | — |

汇总：

- 相关 top1 均值 **0.4705**（区间 0.295~0.576）；对照均值 **0.2538**（区间 0.244~0.269）
- 差距 **0.2167** —— 拉得开，不是"都是 0.3 左右分不出"
- 过 0.4 门槛：**8/9** 条相关问句至少命中 1 条
- 过 0.5 门槛：只剩 **3/9**
- schema 分（0.41~0.58）与 fact 分（0.42~0.76）**同尺度可比** —— 说明命中确实是语义相关，
  不是噪音

## 三、结论

1. **L6 有消费价值，正路可用。** 相关问句能把 schema 拉进 0.45 以上，对照组压在 0.27 以下，
   0.4 这个门槛天然干净（对照最高 0.269，仍低于它）。
2. **不该默认关整条 L6**，也不该把阈值提到 0.5——那会砍掉 6/9 的命中。
3. 之前"一大堆无关内容"的来源不是正路，而是**反路（证据反查，不看 query）+ RRF 覆盖分数 +
   独立配额不受 limit 约束**三件叠加。
4. 两个实测边界：
   - 问得越具体，正路反而越"贪"：`hy-mem 的写锁粒度是多少` 让 6 条 schema 全过 0.4
     → `schema_limit` 必须收小（默认 2~3，不是 10）
   - 最该由 L6 回答的元问题（`他的工程习惯是什么`）只有 0.295，未过门槛
     → 靠 schema 兜住"人设类"提问目前做不到，别承诺这个能力

## 四、据此定的检索口径

| 项 | 决定 | 依据 |
|---|---|---|
| 正路（语义） | **默认开，阈值 0.4** | 8/9 命中，对照全在 0.27 以下 |
| 反路（证据反查） | **默认关**，`--schema-evidence` 显式开 | 不看 query，是"一大堆"的主因 |
| `schema_limit` | **默认 3**（上限 10） | 具体问句会把 6 条全带进来 |
| 分数与排序 | 按语义分展示与排序，不用 RRF 分 | RRF 分 0.01~0.03 与相似度不是一个尺度 |
| 呈现 | schema 独立一节 / 独立 key，不占 `limit`、不进 `results` | 防止 normal 不足时补位冒充搜索结果 |
