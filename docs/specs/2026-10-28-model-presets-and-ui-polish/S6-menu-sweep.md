# S6 · 新增 scripts/test_menu.py：每个菜单都真的能进去

> 父级：`../00-contract.md`　｜　契约条款：C8　｜　状态：已实现

## 为什么要单开一套

用户原话：「你写一个 UI 测试脚本吧，要保证 cli 每个菜单都正常。」

`test_ui.py` 测的是按键解码与行编辑（单控件），`test_cli.py` 测的是子命令（无界面）。
中间那层「界面把命令接错、或者某个页面进去就抛异常」一直没人管 ——
旧版 11 项主菜单 + 13 项设置中心，全靠手点。

## 覆盖

| 节 | 内容 |
| --- | --- |
| 注册表 | 18 条命令：名称不重复、别名不冲突、usage/summary 齐全、`find_command` 认得每个名字与别名 |
| **旧菜单映射** | 旧 11 项主菜单 + 7 项设置不落地，全部映射到命令；缺一条就 FAIL |
| 切词与旗标 | 引号、Windows 反斜杠、`--opt=value`、未知选项、缺值、`--` |
| 补全 | 命令前缀、`setup ` 子项、`setup em`、`queue r`、无候选 |
| 逐命令 | 18 条命令各跑一遍（假 dispatch），断言透传的 argv、屏幕上的关键文案、缺参数时的用法提示 |
| setup 路由 | `setup` / 6 个 scope / `model` 归一，桩 `run_setup` 只验路由，不碰网络 |
| 未知命令 | 返回 2、给近似建议、会话不退出 |
| 真循环 | 真 `run_menu` + 管道 10 条命令：每条后都回到提示符、无「按任意键」、结果留在滚动区、`exit` 与 EOF 都干净退出 |
| 历史 | 落盘位置、去重、新会话可读、长度上限 |

## 边界

- 不调模型、不碰真库：dispatch 是假的，配置与数据在 `tempfile` 沙箱。
- `setup` 用桩，因为它要发网络请求（那部分由 `test_setup` 用 `netprobe` 桩覆盖）。
- 非 TTY 驱动（`HY_MEM_TUI=0`）：这本身就是「agent 能不能驱动控制台」的证明。
