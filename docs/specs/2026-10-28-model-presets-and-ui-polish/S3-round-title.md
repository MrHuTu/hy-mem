# S3 · 轮次标题与「要不要唤醒 worker」两个多余确认

> 父级：`../00-contract.md`　｜　契约条款：C6 / C7　｜　状态：已实现

## 现象

1. 「写入和查询，执行完成一次之后另起一行，新行的标题头太傻了，不要计数的文本提示。」
2. 「写入的时候，还提示要不要唤醒 work，这有必要吗？默认就唤醒了消费者，
   这个确认还要不要唤醒是不是多余操作？」

## 根因

- 旧 `page_add` / `page_search` 在第 2 轮起打印 `写记忆（第 2 条）` / `检索（第 2 次）`，
  而屏幕上本来就接着上一条结果，再顶一个带计数的装饰框纯属噪音。
- `add --async` 的回执里已经写着「已自动拉起后台消费进程」，交互层却又问
  「现在就跑一次 worker 落库？」—— 问的是一件**已经发生**的事；选「否」之后
  用户还得自己去队列页，等于把自动化又退化成手工。

## 改法

两条都不是"改文案"，而是在控制台重构（S4）里**整段删掉**：

- 没有轮次标题 —— 命令式控制台里每次操作就是一次命令，屏幕上只有提示符和结果；
- 没有 worker 确认 —— `add` 默认 `--async`，回执带后台状态，另附一行
  「已入队，后台消费者会自动落库；此刻 search 还查不到是正常的」。
  要同步写用 `--sync`，要立刻清空队列用 `queue run`。

## 验证

- `scripts/test_menu.py`：`add 默认异步`、`add 回执说明后台落库`、`--sync 不再提示后台`、
  真 `run_menu` 输出里 `按任意键` 出现次数为 0。
- `scripts/test_ui.py`：连写两条的输出里不含 `第 2 条` / `再写一条` / `按任意键`。
