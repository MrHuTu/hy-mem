## 0. 现象（用户原话）

1. 「检索功能，写入记忆功能，目前还只能写入一条，操作完成后按任意键会回到主界面」→
   要求：**每次操作完成后可以继续操作，也可以正常退出回主界面**。
2. 「设置里面，没办法重新设置模型（肯定有切换模型的需要）」→
   要求检查三条路径：**第一次没配好** / **第二次复用配置** / **第二次重新修改配置**。

## 1. 契约区 —— 实现与测试都只认这里

| # | 条款 | 约定 | 落地位置 |
| --- | --- | --- | --- |
| C1 | 页面级循环 | 可重复操作的功能页（写记忆 / 检索）在每次操作完成后**默认停留在本页**，用户显式选择「回主界面」或按 Esc 才返回 | `cli/menu.py` |
| C2 | 零成本续用 | 一次操作结束后**不得插入任何确认或菜单**，直接把输入提示交还给用户；退出统一为「输入留空回车」（Esc / Ctrl+C 同效）。禁止用 y/n 或列表二选一承载「继续 / 退出」——那让每次操作都多一次按键与一次光标移动，且与「空行＝不写了」的既有语义重复 | `cli/menu.py::page_add` / `page_search` |
| C3 | 密钥来源单一 | 嵌入模型的密钥一律按 `[预设 key_env, 配置 keyEnv, MEMORY_EMBEDDER_API_KEY]` 找**第一个有值的变量名**，取到就继承且不落盘；与 `step_llm` 完全对称 | `cli/setup_wizard.py::step_embedding` |
| C4 | 配置不完整也能改 | 当前配置为空（baseUrl / model 缺失，即"第一次没配好"）时，选预设必须能用环境变量里的 key 完成配置，**不得强制手填** | 同上 |
| C5 | 换模型不默认毁数据 | 换嵌入模型后的「重建数据目录」改为三选，**默认「先不重建」**；重建只在用户显式选择时执行 | `cli/setup_wizard.py::_commit` |
| C6 | 换模型必须能成功 | 换到同一端点的另一模型、换到新端点（有对应 key）、配置从空开始 —— 三条路径都必须落到「配置已写入」 | 全流程 |

## 5. 结论

- **C1 / C2（默认续用）**：`page_add` / `page_search` 两个页面一次性操作结束后不再弹任何菜单，
  直接把输入提示交还；不输入内容直接回车即回主界面。真 CLI 驱动实测：连写两条 +
  连查两次，全程零额外按键，第 3 轮空回车打出「（没有输入内容，已回主界面）」。
