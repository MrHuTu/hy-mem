# R4 · 换模型默认重建数据目录（回车即清库）

> 父级：`../00-contract.md`　｜　契约条款：C5 / C6　｜　状态：✓ 已修

## 现象

换嵌入模型后，`_commit()` 依次问两个默认「是」的确认：

```
i 嵌入模型发生变化：qwen3.7-text-embedding-flash → text-embedding-v4（建议重建）
数据目录已有 338 KB / 10 个文件。不重建的话……检索结果会失真。
› 备份并重建数据目录？（原数据会复制一份 .bak-时间戳） [Y/n]:
› 写入配置？ [Y/n]:
```

两个确认都吃「回车」。用户一路回车，等于**换模型的同时把记忆库清空**（只留在 `.bak-*` 里）。
他一旦意识到这点，就会不敢再改模型 —— 这正是「没办法重新设置模型」的心理来源。
更糟的是 `Esc` 在 `allow_cancel=False` 下直接返回 default（= 是），想取消却触发了重建。

## 根因

把「破坏性操作」和「常规确认」放在同一条 `default=True` 的连问链里，且没有「只改配置、先不重建」
这个出口。用户只有「重建」和「放弃整次修改」两条路。

## 改法

`changed` 且有数据文件时，改为**三选**（`tui.select`，默认第 2 项「先不重建」）：

| 选项 | 含义 |
| --- | --- |
| 重建（备份后清空，推荐） | 旧向量与新模型不兼容，混用会让检索失真 |
| **先不重建（默认）** | 只改配置；旧向量仍在，检索可能失真，之后可在 设置 → 存储 里清空重建 |
| 放弃这次修改 | 不改配置也不动数据 |

选「放弃」→ `raise tui.Aborted()`（设置页会提示「已取消」，比静默 return 0 更清楚）。
空库（无数据文件）不提问，直接改配置 —— 没有东西可重建。

## 红 → 绿

修前：设置 → 向量模型 → 选 `text-embedding-v4` → 两个回车 → `data.bak-20261028-181913` 生成，
数据目录被清空（10 个文件 → 0）。
修后：同路径 → 出现三选项，回车 = 先不重建 → 配置写入新 model，`data` 目录 10 个文件**原样还在**；
显式选「重建」才生成 `.bak-*`。

## 回滚

回滚后恢复「默认重建」行为；已产生的 `.bak-*` 与清空后的库不受影响（数据在备份里）。
