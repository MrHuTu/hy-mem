# R2 · 写记忆的「再写一条？」会误退

> 父级：`../00-contract.md`　｜　契约条款：C1 / C2　｜　状态：✓ 已修

## 现象

写记忆本来已经支持连写（`page_add` 是循环），但用户体感是「只能写一条，按任意键就回主界面」。

## 根因

循环靠 `tui.confirm("再写一条？", default=True)` 维持。这个控件在真实终端里：

| 按键 | 行为 |
| --- | --- |
| `y` / 回车 | 继续 |
| `n` | 退出 |
| **其它任何键**（空格、数字、字母、方向键） | **完全无响应**，界面像卡住 |
| `Esc` | 返回 default（= 继续） |

于是用户敲了空格或随手按了某个键 → 没反应 → 再按几次 → 按到 `n` 或 `Ctrl+C` → 回到主界面。
他的结论自然是「写完一条就退出」。这与 `page_search` 是同一类问题：**用 y/n 承载「继续/退出」语义**。

## 改法

`page_add` 保持循环，但**删掉每条之后的追问**：写完一条直接进入下一条的正文输入。

退出只有一种显式动作 —— **不输入内容直接回车**（Esc / Ctrl+C / EOF 同效，直接 `return`）。
多行正文本来就以空行收尾，空行已经表示「这条写完了」；在下一轮的开头再看见一个空的正文提示，
敲回车自然读作「不写了」，与前者语义一致。

提示语随轮次切换：第 1 轮 `一行一条最好…空行结束本条；Ctrl+C 取消。`，
第 2 轮起 `接着写；不输入内容直接回车 = 回主界面。`；退出时打印 `（没有输入内容，已回主界面）`。

初版曾用 `_ask_write_again()`（`tui.select` 二选一）收尾，2026-10-28 用户澄清后删除：
「写记忆 / 检索 一条完成之后应该默认继续，而不是强行让用户二选一」。

写失败时同样停在会话里继续（原本就是这样，不改成退出）。

## 红 → 绿

修前：`drive_menu.py … "0\n一\n\n\n\nn\n\n11\n"` —— 第二条提示出现，但这是 `n`（显式否）造成的，
无法区分「用户主动结束」与「误触」。真正的问题是空键/其它键无响应。

初版修后（二选一）虽然能连写，但每条之后多一次菜单。2026-10-28 改为默认续用后，
真 CLI 实跑 `"1\n第一条\n\n\ny\nn\n第二条\n\n\ny\nn\n\n12\n"`：

```
写记忆
  一行一条最好（混在一起会稀释向量）。空行结束本条；Ctrl+C 取消。
  ✓ 已入队 1 个任务（job 1..1）…
──────────────
写记忆（第 2 条）          ← 中间没有任何「继续 / 回主界面」
  接着写；不输入内容直接回车 = 回主界面。
  ✓ 已入队 1 个任务（job 2..2）…
──────────────
写记忆（第 3 条）
  │ （没有输入内容，已回主界面）
按任意键继续…              ← 空回车才回主界面
```

## 回滚

回滚后 `page_add` 恢复 `confirm` 语义；不影响已写数据。
